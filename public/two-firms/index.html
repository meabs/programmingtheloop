Two firms, one model

Two rival subscription businesses start level and face the same market for 36 months. One delivers software in an AI-heavy way; one is a traditional team. Change the assumptions below and see which ends up with more cash.

This page loads its simulator as an ES module, which browsers block on file://. Serve the folder instead, e.g. python3 -m http.server inside web/, then open localhost:8000.

This is a model, not a forecast. Every coefficient is invented for illustration, and changing an input explores a hypothetical scenario. The numbers describe how the simulator behaves, not how real companies perform. "AI-heavy" means one firm delivers more work with cheaper staff, more defects and lighter review. It does not model a company that is AI-native in how it is run. What is worth taking away is which assumptions the answer is sensitive to.

Things worth trying

  • Drag defect factor from 1.0 to 1.7 and watch the win rate collapse. It is the steepest lever in the model.
  • Move the debt level where incidents begin from 28 up to 60. A single threshold I picked decides a lot of the answer.
  • Change the common overhead and watch nothing happen: both firms pay it, so it cancels out of the gap.
  • Set decision cadence to 6 months. Almost nothing happens: the "agility" advantage is barely modelled.
  • Raise capacity and watch incidents climb: more output means more technical debt.

Runs entirely in your browser. The JavaScript simulator is a port of the Python one and is checked against it on tens of thousands of fixed-seed comparisons, including the random number stream and every shared assumption on this page. Win rate means "AI-heavy finishes with more cash than traditional", with a 95% interval from the number of runs. The code still calls this firm "AI-native"; the label is the only thing that changed.
