---
title: "8. Review, merging and risk"
description: Chapter 8 — match review depth to risk and inspect evidence.
---

Chapter 8 treats review as a decision about the diff, the evidence and the consequences of failure. It describes risk tiers and asks how much human review is warranted for the change at hand.

The worked example asks the reviewer to inspect both the code and the evidence generated by the workflow. Chapter 8’s recommendation is to grade changes and then review them, rather than using an agent’s confident summary as the decision.

The chapter grades by reversibility, blast radius and verification strength. Evidence comes before code. Review should match the tier; repeated review feedback may point to a harness problem that should be fixed once. A different model can filter a diff, but it is not a verdict.

## Try this

Classify a proposed change by impact and reversibility. Inspect the full diff, the tests, any changed verification code and the run evidence. Increase independent review for high-impact or difficult-to-reverse changes.

Keep diffs small, separate structural and behavioral changes into distinct commits, and lower a change category’s review tier only when accumulated evidence justifies it.
