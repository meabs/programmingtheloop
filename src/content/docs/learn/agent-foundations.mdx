This pathway combines Chapters 1 and 2: understand the agent’s working loop, then make the task and its success conditions explicit.

## What a coding agent does

The book treats an agent as a system that receives a task and context, uses tools to inspect or change a repository, and reports what it did. Its useful output depends on the information available, the tools it can use and the checks that constrain the work.

## Facts, checks and upkeep

Repository guidance can help when it is accurate, relevant and maintained. Every added guide, script or generated map also creates an upkeep obligation. Chapter 1 recommends asking what problem a practice solves, what evidence supports it and what maintenance it requires.

## Briefs, plans and specifications

The book distinguishes the request, an implementation plan and executable acceptance checks. A plan can organise work but does not establish correctness. A clear brief names observable behavior and how it will be checked.

## Try this

Take one recent task and write down its user-visible behavior, constraints, prerequisites and an executable check. Identify anything that depends on a service or repository the agent cannot inspect. Compare the brief with [the verification lesson](/learn/proof-not-promises/) before handing it over.
