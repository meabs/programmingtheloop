This chapter is deliberately short: none of my experiments measured parallel working as such. What follows is judgement, other practitioners’ experience, and one lesson from my own trials. Make one agent reliable on a kind of task before you run several, and when you do, spend your effort on **isolation**: each agent must see exactly what it should and nothing else.

## Isolation: files and state

In my trials, agents read other runs’ files off the disk and cloned code from the internet when they could (Chapter 9). Agents use whatever they can reach, so you have to enforce what’s reachable. Asking nicely doesn’t work.

In the worked example, `run_live.sh` starts inventory on port 8001 and the storefront on 8000. Two agents running it at once would collide on the ports; if inventory had a real database, they’d share its data. Parallel-safe means a port and a database per run. Cloud agents fix *local* shared state (ports, Docker, caches, the file system). They do not fix *external* shared state: staging databases, queues, object stores and third-party sandboxes still need isolation of their own.

## Costs of coordination

Before parallelising, count them honestly: review, merging, environment, and your own attention. Ten small PRs are quicker to review than one huge one, but not quicker than three.

**Recommendation: a progression, not a jump.** Move on only when verification is strong enough that reviewing results, not supervising work, is the bottleneck: one supervised agent; one in the background; subagents for search and summarising; a few parallel agents on independent, well-specified tasks, each fully isolated; then a coordinator that assigns work from a plan and gathers results.

## Checklist

- [ ] Make one agent reliable on a task type before parallelising it.
- [ ] Isolate files *and* state: ports, databases, caches, credentials.
- [ ] Cloud agents isolate the machine, not external databases, staging or queues.
- [ ] Assume agents will use anything they can reach; enforce what’s reachable (Chapter 9).
- [ ] Count review, merge and attention costs before adding agents.
- [ ] Keep one point of control.
