title: "7. Parallel agents"
description: Chapter 7 — consider isolation, shared state and coordination costs.
---

Chapter 7 focuses on isolation of files and state, the risk of agents interfering through shared work, and the coordination cost of splitting a task. Parallelism can increase throughput only when the work can be separated and integrated safely.

The source discusses slop, shared state and cloud agents as operational concerns. It does not present a universal throughput multiplier; evaluation needs to count coordination and integration work as well as individual agent time.

The book recommends a progression: first one supervised agent, then one in the background, then subagents for search and summarising, then a few parallel agents on independent, well-specified tasks with full isolation, and only later a coordinator. Move on when verification is strong enough that reviewing results, rather than supervising work, is the bottleneck.

## Try this

Before parallelising, define file ownership, shared interfaces, branch boundaries and how conflicts will be resolved. Decide which changes require serialization and include review and merge effort in your assessment.

Check shared resources too: ports, databases, caches, credentials, queues and external services. A cloud agent’s isolated machine does not isolate those external systems. Keep one point of control.
