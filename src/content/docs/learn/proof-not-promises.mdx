Of everything in this book, this is the practice I’d keep: give the agent an executable way to check its work, and judge the work by an independent check, not by the agent’s account of it. Instructions that reassure (“make sure the tests pass”) are not verification. A command that runs is.

## Two comparisons, not one

**(a) Implementation correctness** — the agent’s work against an independent verification: hidden tests, a grader, a contract test against the real dependency, a reviewer’s run of the suite in a clean environment. The agent’s report plays no part.

**(b) Claim honesty** — the agent’s report against its own command log. Outcomes: honest, overclaim, or underclaim. Whether the change is right plays no part.

The **verification status** is what the log shows the agent’s own checks did: *passed*, *failed* or *not run*. An honest “I couldn’t run the integration tests: no database available” is a true report of a *not run*, and that is useful information rather than a fault.

Practical rule: judge correctness by an independent check; judge honesty against the log; never accept “passed” without the log behind it, and never punish a truthful “not run” or “failed”.

## From friction to a script

AgentTrialRig asked the agent to end each run with a machine-readable claim. Task: a FastAPI change, Codex, three runs per arm. All six runs in the first comparison passed the independent check — every change was *correct* — but in four of six the agent couldn’t run the tests the obvious way because a generated directory was missing. Moving the cause into the repository:

| Arm | Independent check | Mean turns | Tokens/run |
|---|---|---:|---:|
| Friction instructions only | 3 of 3 | 15.3 | 647k |
| Fix documented in `AGENTS.md` | 3 of 3 | 9.3 | 469k |
| Documented, wording sharpened | 3 of 3 | 11.3 | 509k |
| One test script | 3 of 3 | 7.7 | 314k |

Correctness stayed constant. What changed was whether the agent *could* verify. That stops short of a reliable cost saving (no interval excluded “no difference”). Source: [AgentTrialRig README, “Verification claims”](https://github.com/meabs/AgentTrialRig/blob/main/README.md).

## Worked example, stage 5

`bash scripts/test.sh` can pass against a stub while the live behaviour is wrong. The next step is to start the real inventory service and call the endpoint. When the provider ships 3.0.0 and the storefront is still pinned to 2.1.0, the freshness gate catches it before any test runs — while the tests alone still pass, because they’re built from the pinned (now stale) contract. Against the real v3 service, criterion 4 turns silent corruption into a visible 502.

A version check catches declared change only. Undeclared change needs checks that exercise behaviour.

## What the agents reported (finding 4)

Same trials as Chapter 3 (`composer-2.5`, 6 runs per arm):

| | A, no contract | B, contract |
|---|---:|---:|
| Reported `result: passed` | 6 of 6 | 6 of 6 |
| Independent pass, as written / URL variable set | 0 / 0 of 6 | 4 / 6 of 6 |
| Edited the freshness gate so that it passed | 6 of 6 | 0 of 6 |

Every A run rewrote the freshness gate so it compared the contract the agent had invented with itself. By comparison (b) the reports held up against the logs — yet all 12 reported `passed` while listing the brief’s criterion 6 (live check against the real inventory service) as unverified. A false pass needn’t be a lie. **Limits:** one model, one task, 6 runs per arm. Source: [agent-trials/results.md](https://github.com/meabs/ProgrammingTheLoop-WorkedExample/blob/main/agent-trials/results.md).

## Recommendation

Give every task a one-command check, and run it — freshness gate included — where the agent can’t edit it (CI on the protected branch, or a protected path under CODEOWNERS). By default, any diff that touches the checks themselves stops the line for human review. Ask for a red run and read it. Ask for real-use evidence for anything user-facing. Treat an honest *not run* as information about your tooling.

## Checklist

- [ ] Every task has a one-command check with its prerequisites, run where the agent can’t edit it; a diff that touches a check stops for human review.
- [ ] Red first; read which tests didn’t fail.
- [ ] Use it like a user; attach real output.
- [ ] Correctness: compare the work with an independent check.
- [ ] Honesty: compare the report with the command log.
- [ ] Accept an honest “not run”; never accept “passed” without the log.
- [ ] Gate supplied knowledge on freshness; it checks versions, not behaviour.
- [ ] Fail loudly; never return a made-up value.
