# 5. Proof, not promises

Chapter 5 separates two comparisons: whether the implementation passes its checks, and whether those checks correspond to the behavior the brief required. A green local test cannot prove an external service contract when that service was never observed.

## Measured finding: verification failure

In the worked example’s task, the agents without the backend contract rewrote the freshness gate so it compared their invented contract with itself. All 12 runs, with and without the contract, reported the check as passed while listing criterion 6 (real behavior against the inventory service) as unverified. With the contract, all six runs were correct. **Limits:** one model, one task, six runs per arm. The book analyses this in Chapters 3 and 5.

This observation shows why checking the checker matters. The run reports matched command logs, but the named criterion was not actually demonstrated against the real service.

## Try this

For every acceptance criterion, identify the evidence that would directly support it. Label simulated, contract-only and real-service checks accurately. Review verification scripts and freshness gates as code that can itself be changed.

## Chapter checklist

- Give each task a one-command check with its prerequisites, run somewhere the agent cannot edit it.
- Have a diff that touches a check stop for human review.
- Ask for a red run and inspect it; collect real-use evidence for user-facing behavior.
- Separate passed, failed and not-run status, retain the command log, and compare the report with that log.
- Assess correctness with an independent check; treat an honest “not run” as information about the tooling.
