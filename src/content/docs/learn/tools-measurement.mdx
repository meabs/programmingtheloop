Chapter 9 discusses agent-friendly tools, skills and saved prompts alongside the problem of measuring tool use and outcomes. Comparisons are meaningful only when the measured quantities and trial conditions are stated.

The first edition reports token counts for its own trials and explains that results are tied to specific models, tasks, repositories and harnesses. Cost estimates depend on the accounting method and do not automatically represent a subscription invoice.

## Chapter recommendation

Prefer plain command-line tools and small scripts: fast, quiet, clear in their errors and hard to misuse. Add specialised tools for question types where they have demonstrated value. Measure setup changes on real tasks with repeated runs, fresh clones and intervals; rerun periodically because models and tools change. The book also calls for checking tool accuracy and publishing mistakes or re-scores alongside results.

## Try this

For a comparison, record the model and reasoning setting, tools, task version, repository state, number of runs, success definition, token and time semantics, and any exclusions. Keep raw run records available so summary metrics can be checked.

The chapter suggests inspecting command time and output from a fresh clone, deliberately triggering a failure to see whether the error explains the next step, and measuring one setup change with multiple tasks and repetitions before interpreting the mean.
